## 一、冷启动总体方案（基于项目特点的打法）

### 1.1 项目最硬的 4 个特点（冷启动弹药）

结合 `README.md`、架构文档与 `bridge.md` 实测，HiveMTK 对外可讲的"硬货"有且只有这几个，**全部竞品不具备**：

| # | 特点（项目真实能力） | 冷启动钩子 | 竞品对照 |
|---|----------------------|-----------|---------|
| 1 | **七端打通**：抖音/快手/小红书/闲鱼/TikTok/微信/短信/邮件统一收件箱 | "一个后台管 7 个平台的私信" | 源雀/MoChat 只做企微 1 端；Mautic 只邮件 |
| 2 | **Chrome 扩展桥接**（`bridge.md`）：抖音/小红书/TikTok 网页私信实时接入 AI 智能体，无需官方 API | "不接 API、不养号、不封号，装个插件就把三大平台的私信变成 AI 客服" | 全行业几乎没有，演示性极强 |
| 3 | **ReAct 自主智能体**：41 个工具、能自己决定"下一步调什么"，不是写死工作流 | "AI 不是按剧本回复，是真能自己干活" | Dify/FastGPT 是写死工作流；n8n 无社媒触达 |
| 4 | **数据零出域**：本地推理栈（llama.cpp + bge-m3 + bge-reranker）+ FRP 私域穿透，Docker 5 分钟起 | "数据不出你内网，合规无风险" | 微伴/尘锋/小鹅通全是 SaaS 出域 |

> ⚠️ **一条铁律**：任何一次对外宣传，**只讲其中一个钩子**，不同时讲四个。初期主推 **钩子 1+2（七端 + Chrome 插件桥接）**——因为它 demo 最直观、最不像任何竞品、最容易被技术圈转发。

### 1.2 一句话定位（三选一，别全说）

- **主推版（推荐，前 4 周用）**：*“装一个浏览器插件，把抖音/小红书/TikTok 的私信变成 7×24 在线的 AI 客服——数据全程留在你自己的服务器。”*
- **技术版（Show HN / r/selfhosted 用）**：*“HiveMTK: an open-source, self-hosted private-domain marketing OS. 7 social channels, a ReAct agent with 41 tools, and 100% on-prem inference stack.”*
- **合规版（金融/医疗/政务客户用）**：*“不碰 SaaS、不传数据、不养号封号——私有化部署的 AI 私域营销系统。”*

### 1.3 北极星指标与阶段目标

```
北极星：GitHub + Gitee Star（双仓合计）
路径：0 → 100（W1-4）→ 1000（W5-8）→ 商业闭环（W9-12）
     └ 私域社群承接：微信群 0 → 200 → 1500
     └ 转化验证：5 个企业 POC（W8）→ 3 个付费客户（W12）
```

### 1.4 核心打法矩阵（为什么适合 HiveMTK）

| 打法 | 为什么适合本项目 | 不适合的项目 |
|------|----------------|-------------|
| **Demo 优先（bridge 插件实拍）** | Chrome 插件桥接肉眼可见，比架构图更有说服力 | 后端框架类项目 |
| **双仓 + 中文私域** | 中文 SCRM 用户都在微信，必须接住流量 | 纯英文开源项目 |
| **Build in Public** | 92 模块 + 41 工具，每天有"今日 build"素材 | 已成型无迭代的项目 |
| **48h 集中爆破** | 七端 + 插件这一钩子新闻性强，适合一次打透 | 长尾慢热品类 |
