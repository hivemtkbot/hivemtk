## 1. 适用范围

本文档说明 HiveMtk 用户在欧盟 / 欧洲经济区（EEA）部署、运营时，如何满足 GDPR（EU 2016/679）对**个人数据**（personal data）处理的核心要求。

### 1.1 角色界定

| GDPR 角色 | 本项目定位 | 说明 |
|-----------|-----------|------|
| **数据控制者 (Controller)** | 客户（部署方） | 决定处理目的与方式 |
| **数据处理者 (Processor)** | HiveMtk 产品（开源代码） | 按客户指示处理，不独立决定目的 |
| **数据主体 (Data Subject)** | 最终用户（访客/粉丝） | 其个人数据被处理 |

> **重要声明**:本项目以 AGPL-3.0 开源、以**私域单租户**形态部署在客户自有网络，平台端不接触业务数据。因此 GDPR 合规责任主要由部署方（控制者）承担，HiveMtk 提供**技术能力支撑**。本文档是给部署方与二次开发者的**合规自检清单**，不构成法律意见。

### 1.2 处理的数据类型

| 数据类型 | 示例 | 是否个人数据 |
|----------|------|-------------|
| 账号信息 | 用户名、邮箱、手机号 | ✅ |
| 会话内容 | 聊天记录、私信 | ✅（可能含敏感内容） |
| 客户画像 | 标签、RFM 分层、OneID | ✅ |
| 行为日志 | 访问/操作日志（含 IP） | ✅ |
| 渠道账号凭据 | AppSecret / Token / AK/SK | ✅（加密存储） |
| 营销内容 | 话术、FAQ、SOP | ⚠️ 视内容而定 |

## 2. 核心控制项与实施证据

### 2.1 合法性基础 (Art. 6)

| 合法性基础 | 本项目支撑 | 证据 |
|-----------|-----------|------|
| 履行合同 / 服务 | 客服对话、订单处理 | 产品功能设计即业务所需 |
| 合法利益 | 营销自动化、防欺诈 | 需部署方做 LIA 评估 |
| 用户同意 | 主动营销触达 | 需部署方获取并留存同意记录 |

> ⚠️ 主动触达模块（短信/邮件/私信）属 GDPR 高关注场景，部署方须确保有合法同意或合法利益基础。见 [DISCLAIMER.md](../DISCLAIMER.md)。

### 2.2 数据最小化 (Art. 5(1)(c))

| 控制项 | 实施证据 |
|--------|---------|
| 仅收集业务必要字段 | DTO 层明确字段白名单，不整表透传 |
| 日志脱敏 | `user-server/internal/middleware/sanitize.go` 手机/邮箱/身份证自动脱敏 |
| 响应掩码 | 敏感凭据返回统一 `*_masked` |

### 2.3 数据安全 (Art. 32)

| 控制项 | 实施证据 |
|--------|---------|
| 传输加密 | TLS 1.2+（HTTPS/WSS 强制） |
| 存储加密 | 密码 bcrypt(cost=12)、敏感字段 AES-256-GCM |
| 凭据保护 | AppSecret/Token/AK/SK AES-256-GCM 加密落库 |
| 访问控制 | RBAC（admin/manager/agent/user）+ 行级 data_scope |
| 审计日志 | `audit_logs` 表记录 who/when/from_ip/action/resource/result/trace_id |
| 可观测（私域） | 无外部监控 → 应用层日志 + `layer_decision_logs`/`rag_query_logs` 审计表落库 |

### 2.4 数据主体权利 (Art. 15-22)

| 权利 | 本项目技术支撑 |
|------|---------------|
| 访问权 (Art.15) | 客户 360 视图、会话查询 API |
| 更正权 (Art.16) | 客户资料编辑 API |
| 删除权 / 被遗忘权 (Art.17) | 提供客户删除入口（部署方需配置） |
| 数据可携权 (Art.20) | 导出能力（部署方可扩展） |
| 限制处理 (Art.18) | 数据状态字段支持冻结 |

> ⚠️ 数据主体权利的**行使流程**（身份验证、时限 30 天、跨境传输评估等）属控制者义务，HiveMtk 仅提供技术接口，需部署方落地流程。

### 2.5 跨境传输 (Art. 44-49)

| 场景 | 评估 | 建议 |
|------|------|------|
| 本地推理栈（LLM/Embedding/Rerank） | ✅ 数据零出域 | 首选方案，无跨境传输 |
| 可选云端 LLM（DeepSeek/OpenAI 等） | ⚠️ 传输 prompt | 须评估目的地国家充分性认定 / SCC；PII 本地脱敏后再调用 |
| 平台端心跳 | ✅ 仅元数据 | 不含业务/个人数据 |

### 2.6 记录保存 (Art. 30)

| 记录 | 存储 | 保留期建议 |
|------|------|-----------|
| 处理活动记录 (RoPA) | 部署方维护 | 持续 |
| 审计日志 | `audit_logs` 表 | ≥ 1 年 |
| 对话/会话 | 业务表 | 按业务需求，支持清理 |

## 3. 隐私设计 (Privacy by Design, Art. 25)

| 原则 | 本项目落实 |
|------|-----------|
| 数据最小化 | DTO 白名单 + 脱敏中间件 |
| 端到端安全 | 五层架构禁止跨层、TLS、AES-256-GCM |
| 默认隐私 | 私域部署默认零出域 |
| 用户可控 | 数据删除/导出接口 |

## 4. 数据处理协议 (DPA)

> 部署方与 HiveMtk 团队签订商务合同时，建议将本说明作为附录。DPA 模板要点：
> - 处理范围、期限、目的
> - 数据主体权利配合义务
> - 数据安全措施（引用本文件 2.3）
> - 违规通知义务（72 小时内，Art. 33）
> - 转委托（sub-processor）清单与事前批准

## 5. 残余风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 云端 LLM 场景跨境传输 | 配置外部 LLM 时 prompt 出境 | 默认本地推理；需外部 LLM 时用标准 SCC + 本地脱敏 |
| 删除权落地不完整 | 关联表（OneID/标签/画像）级联删除需人工配置 | 提供删除脚本模板，部署方执行 |
| 同意管理缺失 | 未内置同意记录模块 | 部署方需在触达前自建同意管理 |
| 管理类义务 | 员工培训、RoPA、DPA 属组织义务 | 需部署方制度配套 |

## 6. 合规自检清单（部署方）

- [ ] 完成合法性基础评估（Art. 6）
- [ ] 本地推理栈部署（零出域），或与云端 LLM 签署 SCC
- [ ] 启用 HTTPS / WSS / 数据库 SSL
- [ ] 配置脱敏中间件为"开启"状态
- [ ] 建立数据主体权利处理流程（访问/删除/导出）
- [ ] 主动触达场景取得同意并留存记录
- [ ] 维护处理活动记录（RoPA）
- [ ] 审计日志保留 ≥ 1 年并可导出
