## 1. 适用范围

依据《信息安全技术 网络安全等级保护基本要求》GB/T 22239-2019，HiveMtk 在以下场景需要满足**三级**要求：

| 行业 | 等保级别 | 说明 |
|------|---------|------|
| 金融（银行/保险/证券） | 三级 | 强制 |
| 医疗（三级医院） | 三级 | 强制 |
| 政务（政府/事业单位） | 三级 | 强制 |
| 能源 / 交通 / 通信 | 三级 | 强制 |
| 互联网 | 二级 | 推荐三级 |
| 一般企业 | 二级 | 推荐三级 |

**定级对象**:私域部署的 HiveMtk 用户端系统（user-server + user-web + 宿主机推理栈），部署于客户内网，单租户。

## 2. 技术控制项概览与实施证据摘要

| 等保层面 | 关键控制项 | 实施证据（摘要） | 详见 |
|---------|-----------|-----------------|------|
| 安全通信网络 | 网络区域划分 / 边界防护 / 通信加密 | 五层架构分层；Nginx + WAF + 防火墙；HTTPS/TLS1.2+、数据库 SSL、Redis TLS | [等保2.0三级合规.md §2](../operations/等保2.0三级合规.md) |
| 安全区域边界 | 访问控制 / 入侵防范 / 恶意代码防范 | Nginx ACL、`/api/bridge/*` Token 鉴权、fail2ban、ClamAV | 同上 §3 |
| 安全计算环境 | 身份鉴别 / 访问控制 / 安全审计 / 数据保密完整 | TOTP MFA、RBAC + 行级 data_scope、`audit_logs` 审计表、bcrypt + AES-256-GCM | 同上 §4 |
| 安全管理中心 | 系统/审计/安全管理三权分立、集中管控 | 审计表只读（禁 UPDATE/DELETE）、配置集中化 | 同上 §5 |
| 安全建设管理 | 定级/方案/开发/测试/验收/测评 | 安全开发规范、五层架构护栏、渗透测试 | 同上 §6 |
| 安全运维管理 | 漏洞管理/备份/变更/应急预案 | Dependabot、每日备份 + 每周恢复演练、季度 PITR 演练 | 同上 §7 + [DR_RECOVERY](../operations/DR_RECOVERY.md) |

**总体符合度**:技术部分 100%（详见 operations 文档 §8 技术指标对照表）；管理部分需客户方配合制度建设。

## 3. 私域部署的特殊设计（无外部监控的替代方案）

针对等保三级"安全管理中心集中管控"要求，私域单租户部署**不依赖外部监控 SaaS**，改为：

| 等保要求 | 私域实现 |
|---------|---------|
| 集中监控 | 应用层日志（`$HOME/.hivemtk/runtime/*.log`）+ 巡检脚本 |
| 集中审计 | `audit_logs` / `layer_decision_logs` / `rag_query_logs` 表落库 |
| 集中告警 | 巡检 SQL 阈值触发 + 日志 grep（见 [AI_AGENT_PERF_DEPLOY.md §6](../operations/AI_AGENT_PERF_DEPLOY.md)） |

> 可选：客户可按等保要求自行部署 Prometheus / ELK / 安全审计平台对接。

## 4. 残余风险

| 风险 | 说明 | 缓解措施 |
|------|------|---------|
| 管理类控制未落地 | 制度建设/人员管理/运维流程属组织义务 | 客户方按 §7 运维管理要求配套 |
| 测评整改闭环 | 现场测评发现的差距项 | HiveMtk 提供技术答疑 + 修复支持 |
| 密钥管理强度 | 依赖部署方妥善保管 .env 密钥 | 强制密钥轮换（90 天）+ 可选 HSM |
| 外部审计对接 | 私域无外部监控，测评取证需人工导出 | 提供巡检/审计导出能力 |
