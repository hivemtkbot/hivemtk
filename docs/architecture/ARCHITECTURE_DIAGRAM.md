### 3.2 依赖方向规则(强制)

| 上层 | 可调用下层 | 禁止反向依赖 |
|---|---|---|
| cmd/api | router / middleware / config | - |
| router | controller / middleware | - |
| controller | service / dto / response / utils | model (不应直接访问) |
| service | model / dto / llm / cache / tools / reach / aiagent / database | - |
| model | database / utils | - |
| llm / cache / tools | database / utils / model | - |
| aiagent | agent / rag / llm / embedding / vector / knowledge / database / utils | 反向被 service 调用; 不依赖业务 service |

**禁止规则**:
- ❌ 业务 service 互相循环依赖
- ❌ controller 直接访问 model(必须经 service)
- ❌ model 持有业务逻辑
- ❌ dto 反向依赖 service

- 三类智能体共享 `internal/aiagent/` 算力层,差异仅在 system prompt + tool 集合 + SOP 绑定。

## 九、架构决策记录(ADR)

### ADR-001:五层架构而非 DDD

**决策**: 采用经典五层架构,不使用 DDD 完整战术设计。  
**原因**: 团队熟悉度高,实现简单,业务模块已成型,DDD 重构成本大。  
**生效**: 2026-01-01 起所有新模块。

### ADR-002:GORM 而非 sqlx/ent

**决策**: 全栈使用 GORM。  
**原因**: 项目已用 GORM,熟悉度高,文档全,生态好。  
**影响**: 复杂查询用 Raw SQL + Scan,避免 N+1。

### ADR-003:独立部署单实例数据物理隔离

**决策**: 私域独立部署,每个商户独立部署一套完整系统,数据物理隔离。  
**原因**: 客户数据隔离要求高,独立部署保证绝对数据安全,符合业务规模。  
**影响**: 业务表无需多租户字段,独立部署下数据天然隔离。

### ADR-004:AI 销冠不重写已有服务

**决策**: 新增 tools/reach/sales_engine/sop 包,**包装**已有 Service 为 Tool。  
**原因**: 已有 130+ Service 成熟稳定,重写风险大。  
**影响**: 后续 AI 集成只新增调用层。

### ADR-005:LICENSE 3 分钟心跳

**决策**: License 检查每 3 分钟一次,3 次失败退出。  
**原因**: 平衡实时性与服务器压力。  
**生效**: 2026-06 起。
