# HiveMtk 用户端 - 部署架构（用户端视角）

> 用户端独立部署（私域模式）
> 适用版本：2026-07-21
> 本文档聚焦**用户端**部署：客户本地运行的部分

---

## 一、定位与边界

HiveMtk 系统按 **数据主权** 拆分为两端：

| 端 | 所有者 | 运行位置 | 数据 |
|----|-------|----------|------|
| **平台端（Platform）** | 运营方 | 云服务器 | License / 版本 / 元数据 |
| **用户端（User）** | 企业客户 | 客户本地 | 访客对话 / 知识库 / RAG |

**唯一跨域弱依赖**：用户端 `user-server` 经 `PLATFORM_API_URL` 向平台端 `platform-server` 做**低频 HTTPS** 许可/产品同步（几秒一次心跳，**非对话流量**）。

## 三、组件清单

| 组件 | 端 | 运行位置 | 推理栈 | 发布方式 |
|------|----|----------|--------|----------|
| `user-server` | 用户端 | 本地 | 调用本地推理 | 人工 / OTA |
| `user-web` | 用户端 | 本地 / 云端托管回退 | 无 | 人工 / OTA |
| `embed-sdk` | 用户端 | 随 user-web 部署 | 无 | 随 user-web 一起发布 |
| `mtk-llm` | 用户端 | 本地 | 是 | 随 docker-compose 分发 |
| `mtk-embedding` | 用户端 | 本地 | 是 | 随 docker-compose 分发 |
| `mtk-rerank` | 用户端 | 本地 | 是 | 随 docker-compose 分发 |
| `PostgreSQL user_db` | 用户端 | 本地 | - | 命名卷持久化 |
| `Redis` | 用户端 | 本地 | - | 命名卷持久化 |

## 四、通信矩阵

| 调用方 | 被调方 | 协议 | 是否出域 | 说明 |
|--------|--------|------|----------|------|
| 访客浏览器 | user-server | WSS/HTTPS | 经公网 | 网页客服浮标（FRP / 公网）|
| 客户员工 | user-web → user-server | HTTPS | 经公网（云端托管时）| 页面在云，API 回本地 |
| 客户员工 | user-web（本地自托管）→ user-server | HTTP | 不出域 | 完全内网 |
| user-server | platform-server | HTTPS | 出域（低频）| 仅许可/产品同步心跳 |
| user-server | mtk-llm / mtk-embedding / mtk-rerank | HTTP | 不出域 | RAG 检索/生成 |

## 五、dev / prod 模型档

| 档位 | LLM | Embedding | Rerank | 用途 |
|------|-----|-----------|--------|------|
| **dev（轻量，当前默认）** | Qwen2.5-1.5B-Instruct (Q4) | Qwen3-Embedding-0.6B | bge-reranker-base | 本机/小内存部署 |
| **prod（重量）** | Qwen2.5-14B-Instruct (Q4+) | BAAI/bge-m3 (1024 维) | bge-reranker-v2-m3 | 生产质量 |

切换：

```bash
# 模型档位在 .env 中配置（LLM_MODEL_REPO / EMBEDDING_MODEL_ID 等）
make inference-up
```

> **铁律**：embedding 维度硬性 **1024**（与 pgvector 一致）；严禁 `EMBEDDING_ALLOW_FALLBACK=true`（仅单测可开）。

## 六、端口一览（用户端）

| 服务 | 端口 | 说明 |
|------|------|------|
| PG-user | 8202 | 用户端库 |
| Redis | 8203 | 用户端缓存 |
| user-server | 8204 | 对话核心 API/WS |
| mtk-llm | 8207 | llama.cpp |
| mtk-embedding | 8208 | TEI |
| mtk-rerank | 8209 | TEI |

> 平台端端口（8201/8205/8211/8213）不在用户端部署。
> 前端（user-web / embed-sdk）在宿主机构建，dist 由 user-server 静态托管，无独立前端容器。

## 七、容器启动顺序（关键）

```bash
# 1. 启动推理栈（创建 mtk-inference-net 网络）
make inference-up

# 2. 启动用户端（接入 mtk-inference-net 外部网络）
make user-up

# 3. 验证
curl http://localhost:8204/health
```

**禁止反过来启动**：user-server 依赖 mtk-embedding / mtk-rerank 提供 RAG 检索能力，先起 user-server 会导致 RAG 不可用。

## 八、公网可达方案

### 方案 A：有公网 IP / 已备案域名

直接在云服务器上：

```bash
# 把 8204 暴露到公网（注意 HTTPS！）
# HTTPS 终结由外部 CDN / 反代负责（如有需要可自行配置）
```

### 方案 B：无公网 IP（NAT 内网）

使用 **FRP 穿透**：

1. 在轻量云部署 `frps`（配置见 `docs/FRP私域部署指南.md`）
2. 本地机部署 `frpc`，把 `user-server:8204` 映射到 `chat.你的域名.com`
3. 客户官网集成：
   ```html
   <script src="https://chat.你的域名.com/embed/marketing-chat-widget.iife.js"></script>
   ```

> FRP 二进制已随仓库自带于 `offline-deploy/frp/bin/`，v0.70.0 五端；升级用 `offline-deploy/frp/download-frp.sh`。

## 九、风险与边界

- **数据主权**：对话与 RAG 全留本地，平台端只碰许可/产品元数据。
- **FRP 单点**：`chat.你的域名.com` 依赖 frpc 在线；frpc 掉线 → 网页客服不可用，但本地对话不丢。
- **OTA 升级离散**：用户端不强制升级，需记录各客户版本以便支持。
- **CORS**：用户端 API 默认放行 `CORS_ALLOW_ORIGINS_USER` 中配置的域名。
