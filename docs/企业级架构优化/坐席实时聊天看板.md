## 一、设计目标

- **三栏物理布局**：左栏会话队列 / 中栏聊天窗 / 右栏客户 360° 画像
- **AI/人工一键切换**：前端通过统一 `switchSessionHandler(id, handlerType)` 切换
- **零身份伪造**：所有 sender_type / agent_id 由后端从 JWT 上下文派生，前端不可伪造
- **实时推送**：WebSocket 推送新消息、会话状态变更、AI 建议给坐席端
- **客户 360°**：跨会话聚合画像标签、SOP 阶段、历史消息统计

## 二、核心数据模型

| 模型 | 用途 |
| --- | --- |
| `CustomerSession` | 单次会话主表（含 `handler_type` 字段标识 AI/人工） |
| `SessionMessage` | 会话消息流（含 `sender_type`: user/ai/agent） |
| `AgentStatus` | 坐席状态（online/busy/offline + max_sessions） |
| `UserBlacklist` | 用户黑名单（user_id 维度，支持 TTL 过期） |
| `AISuggestion` | AI 实时建议（按会话 ID 聚合） |
| `QuickReply` | 快捷回复（按 category 分类） |
| `SessionTag` | 会话标签（支持搜索/添加/移除） |

### 3.2 接管 / 释放 / 切换（service/customer_session.go）

- **TakeoverByAgent(ctx, req)**：
  1. 校验坐席存在 + 在线 + 容量未满
  2. 幂等：会话已分配给该坐席 → 仅切 handler/status
  3. 接管：减原坐席活跃数 + 分配新坐席 + 加新坐席活跃数
  4. 写 Redis 人工锁（`LockSessionForHuman`，让 AI 推理不再继续）
  5. 推 WebSocket 给访客（`type=agent_joined, handler=human`）和坐席（`session_update`）

- **ReleaseToAI(ctx, req)**：
  1. 校验会话归属该坐席（防越权）
  2. 清空 agent_id / agent_name
  3. handler_type 切回 ai、status 切回 waiting
  4. 减坐席活跃数 + 解 Redis 人工锁
  5. 推 WebSocket 通知

- **SwitchHandler(ctx, req)**：前端统一入口
  - `handler_type=human` → 等价 Takeover
  - `handler_type=ai` → 等价 Release

### 3.3 关键安全设计

- `agent_id` 从 `ctx.user_id`（JWT 中间件注入）派生，前端**禁止伪造**
- 访客请求（带 `chat_channel_id`）的 `sender_type` 被强制覆盖为 `user`
- 所有 WebSocket 推送仅按 agent_id 路由，访客按 session_id 路由

## 四、拉黑 / 解除拉黑

### 4.1 模型 `UserBlacklist`（model/user_blacklist.go）

```go
type UserBlacklist struct {
    ID, OperatorID  uint
    UserID          string         // 维度
    Platform        Platform
    Reason, Source  string         // manual / auto / risk
    SessionID       string         // 拉黑时所在会话（便于审计）
    Active          bool           // 软删除标志
    ExpiresAt       *time.Time     // nil = 永久
    CreatedAt, UpdatedAt time.Time
}
```

- 表名 `user_blacklist`
- 索引：`(user_id, platform, active)`、`session_id`、`operator_id`

### 4.2 拉黑流程（service BlacklistUser）

1. 校验会话存在且 `user_id` 非空
2. 幂等：若 `user_id+platform` 已有 active 记录 → 更新 reason / expires_at
3. 写黑名单（`Active=true`，TTL 可选）
4. **关闭该会话**（`status=closed`）防止继续对话
5. 推 WebSocket：前端 `event=blacklisted`、访客 `handler=human + blacklisted=true`
6. 后续该 user_id 在该 platform 上所有新会话都应被 `IsUserBlacklisted()` 拒绝

### 4.2.1 CreateSession 串联黑名单（2026-07-22 二次审核补全）

`CustomerSessionService.CreateSession` 入口处先调 `preCreateBlacklistGuard`：

- 命中 → 返回 `"该访客已被加入黑名单，无法创建新会话"`，拒绝创建
- 未命中 → 正常创建
- 仅在 `req.UserID != ""` 时校验（匿名访客跳过）

**实现细节**（见 `internal/service/customer_session_blacklist.go`）：
- `preCreateBlacklistGuard(req)` 是独立方法，便于单测覆盖
- 未来扩展风控评分 / 限流只需在该方法中追加守卫
- `CreateSession` 主流程保持简洁（仅 `preCreateBlacklistGuard + Generate + DB Insert`）

防止拉黑后访客通过创建新会话绕过黑名单（**这是 CreateSession 入口的关键安全链**）。

### 4.3 解除拉黑

`UnblacklistUser(userID, platform)`：软删除（`Active=false`），保留审计轨迹。

### 4.4 前端交互

- 右栏"快捷操作" → 点击「拉黑」按钮
- 弹出 prompt 输入拉黑原因
- 调 `blacklistSession(id, reason, ttlHours=0)` → 后端关会话 + 写黑名单
- 列表自动刷新（`loadSessions()`）

## 七、Import Cycle 修复（2026-07-22 方向A 完成）

**已解决**。原 BLOCKED 项已通过 `internal/aiagent/agent/portcontract` 包抽出完成解耦。

### 7.1 问题根因

- `service/tool_ports_adapter.go` 直接 `import "marketing/internal/aiagent/agent/tooluse"`
- 同时 tooluse 内 5 个生产文件（customer_tools.go / business_tools.go / private_message_tools.go / reach_tools.go / reach_integration_adapter.go）反向 `import "marketing/internal/service"`
- 形成 `service → tooluse → service` 的 import cycle，导致 `go build ./...` 与 `go test ./internal/service` 失败

### 7.2 修复方案：portcontract 包抽出

新包 `internal/aiagent/agent/portcontract` 包含所有 Port 接口与 DTO：

| 文件 | 职责 |
| --- | --- |
| `doc.go` | 包说明：设计目标 / 装配时机 / 依赖方向 |
| `customer.go` | `CustomerPort` + `CustomerIdentity` / `CustomerProfileView` |
| `session.go` | `SessionPort` + `CreateSessionInput` / `SendMessageInput` |
| `order.go` | `OrderPort` |
| `followup.go` | `FollowUpPort` + `FollowUpScheduleOptions` |
| `journey_reach.go` | `JourneyPort`（预留） + `ReachPipelinePort`（预留） + `ReachSendInput` |

### 7.3 依赖拓扑修复后

```
修复前（循环）：
  service ──→ tooluse
     ↑          │
     └──────────┘

修复后（单向）：
  service ──→ portcontract ←── tooluse
```

- `service/tool_ports_adapter.go` 改 `import "marketing/internal/aiagent/agent/portcontract"`
- `tooluse/ports.go` 改为 type alias 形式重导出所有类型（`type CustomerPort = portcontract.CustomerPort`）
- 工具内 5 个生产文件**零修改**继续工作
- 14 个测试调用方**零修改**
