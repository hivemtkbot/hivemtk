# 功能模块全景对齐清单

> **关联文档**: `功能模块全景图.md`、`六层物理拓扑对齐清单.md`、`ARCHITECTURE_DIAGRAM.md`  
> **交叉检查依据**: 以 `user-server` 源码符号/路径为准（非设计草案）

本文档固化「功能模块全景图」与现有代码模块的映射关系，明确 5 大功能域下每个子模块的落地路径。

**范围说明**：本清单对应 **Agent 决策闭环**（接入 → 引擎 → 工具/记忆/算力），不是产品全功能目录。营销自动化、团队/系统管理、卡片平台等见 `docs/CROSS_COMPARISON_REPORT.md` 与 `docs/marketing-features/`。

**命名区分（易混）**：

| 概念 | 类型 | 职责 |
|---|---|---|
| `InboxIngressService` | 入站中台 | 标准化 `MessageEvent`、人工锁、AI 串行锁、pending 队列 |

| `MessageHub` 服务 | 消息中心 | 业务侧消息/会话聚合 API |

**接入覆盖缺口（文档诚实标注）**：

- Ingress 能力与 API 已落地（含单测 `inbox_ingress_test.go`）。
- 各渠道 webhook/bot **尚未全部强制**调用 `HandleIngressMessage`（`channelbot/*` 当前无直接引用）；全渠道收敛仍属后续治理项，验证清单见文末。

## 功能域 4 - 分层记忆系统

| 层级 | 介质 | 现状 | 代码路径 |
|---|---|---|---|
| L1 短期活跃记忆 | Redis List / 会话历史 | 已落地 | `internal/aiagent/rag/retrieval/redis_cache.go` + Weave 的 `ChatHistory` 注入 + `runtime/types.go` |
| L2 长期语义记忆 | PGvector | 已落地 | `internal/aiagent/vector/vector_model.go` + `internal/aiagent/knowledge/model/knowledge_merchant.go` |
| L3 业务 SOP 状态 | Redis / PG | 已落地 | `internal/service/sop_service.go` + `sop_loader.go` + `sop_scheduler.go` + `sop_dispatcher.go` |
| L4 业务实体快照 | PostgreSQL | 已落地 | `internal/service/order.go` / `clue.go` / `user.go` 等 |

**补充**：

- **L1**：会话历史由 Weave 截断注入（`MaxHistoryMessages`，默认见 `DefaultWeaveOptions`）；全景图「最近 3 轮」为产品约束，实现以配置/选项为准。
- **L2 提炼**：`internal/aiagent/agent/runtime/publisher_knowledge.go` 异步触发向量化。
- **L3 SOP 阶段**：流程节点可转人工；实现以 SOP 图/执行器为准。
- **L4**：订单 / 线索 / 投诉工单 / RFM 等业务实体。

| 多 LLM 路由 | 已落地 | `dispatcher.go` + `dispatcher_registry.go` + `provider_failover.go` | OpenAI 兼容 |

**部署真相源**：`docker-compose.yml` 本地推理栈注释与服务定义（`mtk-llm` / `mtk-embedding` / `mtk-rerank`）；脚本见 `scripts/inference/`。

> ~~主路径 Ollama~~ 已废弃表述；私域默认栈为 **llama.cpp + TEI**。

**关键约束**（私域部署）：

- ✅ Embedding **必须本地**，禁止静默降级到 LLM 厂商 / hash 伪向量
- ✅ 数据不出域，外部 API 仅用于 LLM 推理（可选）
- ✅ 多厂商场景限流备用 + 熔断降级

                             │ HTTPS / WebSocket
                             ▼

   ┌──────────┐      ┌──────────┐       ┌──────────┐
