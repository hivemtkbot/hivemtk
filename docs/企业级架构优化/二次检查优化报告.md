## 三、Async Goroutine 可靠性（一类问题，多处违规）

### 缺陷 8：异步 goroutine 丢失原 ctx（3 处）— P1 🚫

| 项 | 内容 |
|---|---|
| **文件 1** | `knowledge_base.go:160` `context.WithTimeout(context.Background(), 15*time.Minute)` |
| **文件 2** | `knowledge_service.go:165` 同上 |
| **文件 3** | `knowledge_service.go:749`（Reindex 内嵌 goroutine）同上 |
| **问题** | 异步任务在 HTTP 请求结束后，原 ctx 早已 cancel；但 goroutine 仍按 `context.Background()` 跑 15 分钟，导致：① 客户端取消 → 后端仍继续消耗 embedding/索引资源；② 进程关闭时 goroutine 不会被优雅取消 |
| **修复** | 1) 引入 `pkg/utils/async/background.go`，提供 `RunWithTimeout(ctx, timeout)`：保留原 ctx 的 Value（如 traceID），但 timeout 用 `context.Background()` 做新 ctx；<br>2) 三处调用点替换为 `async.RunWithTimeout(ctx, 15*time.Minute, func(ctx) {...})` |
| **影响范围** | 1 个新工具 + 3 处替换 |

### 缺陷 9：错误吞噬导致文档永久卡住（多处）— P1 🚫
