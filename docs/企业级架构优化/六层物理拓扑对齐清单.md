# 六层物理拓扑对齐清单

> **文档版本**: v1.0
> **生效日期**: 2026-07-22
> **关联文档**:
> - 高层架构: `ARCHITECTURE_DIAGRAM.md`
> - 代码规范: `GO_FIVE_LAYER_ARCHITECTURE.md`
> - 模块全景: `功能模块全景图.md`

本文档固化"六层物理拓扑"与现有代码的逐层映射关系，作为企业级架构优化的基线。

---

## 拓扑总览

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 接入与渠道层 (Webhook / WebSocket -> MessageHub -> InboxService)     │
├────────────────────────────────────────────────────────────────────────┤
│ 2. 智能体运行时 (AgentRuntime: 事件订阅 -> 加载 AgentContext 上下文)   │
├────────────────────────────────────────────────────────────────────────┤
│ 3. 智能体引擎 (决策大脑: 感知 -> 规划 -> 行动 Tool 链 -> 拟人度门禁)    │
├────────────────────────────────────────────────────────────────────────┤
│ 4. 工具注册表 (智能体手脚: customer.* / rag.* / knowledge.*)           │
├────────────────────────────────────────────────────────────────────────┤
│ 5. 记忆系统 (L1 Redis -> L2 pgvector -> L3 SOP -> L4 业务订单)         │
├────────────────────────────────────────────────────────────────────────┤
│ 6. AI 算力底座 (本地向量化 Embedding-server -> 本地 RAG -> 多LLM 路由)  │
└────────────────────────────────────────────────────────────────────────┘
```

## 第 1 层 - 接入与渠道层

| 渠道适配器 | 代码路径 | 职责 |
|---|---|---|
| 网页客服 | `embed-sdk/src/iframe-panel.js` + `user-server/internal/websocket/` | WebSocket 长连接 + 嵌入聊天窗 |
| 闲鱼自动化 | `internal/aiagent/agent/browser/xianyu_ws.go` | 闲鱼 WebSocket 接入 |
| 平台机器人 | `internal/aiagent/agent/browser/platform.go` | 平台端浏览器自动化 |
| TG / WA | `internal/service/telegram.go` / `whatsapp.go` | 外部 webhook 入口 |
| 站内 Web | `user-server/internal/router/chat_routes.go` | `POST /api/chat/ingress` |

**统一消息标准**: `internal/aiagent/agent/runtime/types.go` 中的 `CustomerMessagePayload`。

**统一入口 (待落地)**: `internal/aiagent/agent/inbox/` (MessageHub + InboxService)，由方向 3 实施。

## 第 2 层 - 智能体运行时 (AgentRuntime)

**代码路径**: `internal/aiagent/agent/runtime/`

| 文件 | 职责 |
|---|---|
| `runtime.go` | 运行时主入口 `HandleCustomerMessage`，按 AgentType 路由到 sales/customer_service/hybrid |
| `event_subscriber.go` | 订阅外部事件 (event bus) |
| `publisher.go` | 智能体响应回写到消息中心 |
| `loader.go` | 加载 AgentContext (system prompt + tools + RAG binding) |
| `idempotency.go` | 幂等性保证，避免重复处理 |
| `types.go` | `AgentContext` / `CustomerMessagePayload` / `SalesRequest` / `SalesResponse` 定义 |
| `lifecycle/` (上层) | 运行时生命周期管理 |

**统一接口 (Wiring)**: `cmd/api/main.go` 调用 `runtime.InitGlobalRuntime()` 启动。

---

## 第 3 层 - 智能体引擎 (Decision Engine)

**核心结构**: Perceive (感知) → Plan (规划) → Act (行动) → Gate (门禁) → Memory (记忆)

| 子模块 | 代码路径 | 职责 |
|---|---|---|
| 引擎主体 | `internal/aiagent/agent/agent.go` | 引擎接口与编排 |
| 销冠引擎 | `internal/aiagent/agent/bridge/sales_bridge.go` | 销售场景的 LLM 推理 + 工具调用 |
| 客服引擎 | `internal/aiagent/agent/runtime/runtime.go` (hybrid 分支) | 客服场景的 RAG 优先检索 + LLM 生成 |
| 感知 | `internal/aiagent/rag/customer_service/dialog_manager.go` | 情绪 + 意图识别 (方向 6 实施) |
| 规划 | `internal/aiagent/llm/react_adapter.go` | ReAct 范式 Thought-Action |
| 行动 | `internal/aiagent/agent/tooluse/executor.go` | 工具调度执行器 |
| 门禁 | `internal/aiagent/agent/auto_reply/rule_matcher.go` + 方向 7 HumanEscalation | 拟人度 + 转人工 |

## 第 4 层 - 工具注册表 (Tool Registry)

**代码路径**: `internal/aiagent/agent/tooluse/`

| 文件 | 工具分类 | 工具示例 |
|---|---|---|
| `registry.go` | 工具注册中心 | `Register / Execute / List` |
| `customer_tools.go` | customer.* | `customer.search`, `customer.get`, `customer.tag`, `customer.event` |
| `knowledge_tools.go` | knowledge.* / rag.* | `rag.search`, `script.list`, `objection.match` |
| `reach_tools.go` | reach.* | `sms.send`, `email.send`, `wecom.send`, `whatsapp.send` |
| `business_tools.go` | business.* | `order.query`, `order.create` |
| `private_message_tools.go` | pm.* | 私信卡片生成 / 表单卡片 |
| `decorator.go` | 装饰器链 | `rate_limit → retry → audit → billing` |
| `circuit_breaker.go` | 熔断器 | 工具调用过载保护 |
| `param_validator.go` | 参数校验 | JSON Schema 校验 |
| `dead_letter.go` | 死信队列 | 调用失败兜底 |
| `result_cache.go` | 结果缓存 | 工具幂等结果缓存 |

**统一返回结构** (对齐方向 5 文档):

```go
type ToolResponse struct {
    Status string `json:"status"` // "success" / "error"
    Data   string `json:"data"`   // 给大模型看的结构化结果
}
```

**统一路由中枢**: `RouteToToolRegistry(toolName, parameters) ToolResponse`，由方向 5 实施强化（包含限流、审计、重试、成本监控四道防线）。

## 第 5 层 - 记忆系统 (Memory System)

| 层级 | 介质 | 代码路径 | 职责 |
|---|---|---|---|
| L1 短期活跃 | Redis List (最近 3 轮明文) | `internal/rag/retrieval/redis_cache.go` + `agent/runtime/types.go` (SalesRequest.Content 上下文) | 维持当前会话上下文连贯性 |
| L2 长期语义 | PGvector | `internal/vector/vector_model.go` + `internal/rag/retrieval/vector_retriever.go` + `internal/aiagent/knowledge/model/` | 异步提炼出的用户标签 / 偏好画像 |
| L3 SOP 状态 | Redis Key | `internal/service/sop.go` + `internal/service/sop_loader.go` + `internal/aiagent/agent/runtime/loader.go` (AgentContext) | 业务流程进度 (售前/售中/售后) |
| L4 业务快照 | PostgreSQL | `internal/service/order.go` / `internal/service/clue.go` / `internal/service/user.go` | 订单/工单/未完结投诉实体 |

**写入入口**:
- L1: `runtime.Publisher` 在每次响应后回写
- L2: `knowledge.Service.RefreshUserVector` 异步提炼
- L3: `sop.Service.AdvanceNode` 在状态机推进时写入
- L4: 业务服务事务完成后由 Repository 写入

## 第 6 层 - AI 算力底座 (Compute Substrate)

| 子能力 | 代码路径 | 关键能力 |
|---|---|---|
| Embedding | `internal/aiagent/embedding/embedding.go` | 本地 Go Embedding (字符 n-gram TF-IDF + 随机投影，OpenAI 兼容协议) |
| 向量存储 | `internal/aiagent/vector/vector_model.go` | PGvector CRUD |
| RAG 引擎 | `internal/aiagent/rag/core/rag_engine.go` | BM25 + 向量 + RRF 融合 + Rerank |
| RAG 检索 | `internal/aiagent/rag/retrieval/` | `vector_retriever` / `bm25_retriever` / `hybrid_searcher` / `rrf_fusion` / `reranker` |
| LLM 调度 | `internal/aiagent/llm/dispatcher.go` + `dispatcher_registry.go` | 6 厂商 8 场景，限流备用 + 熔断降级 |
| LLM 路由 | `internal/aiagent/llm/provider_failover.go` | Provider 故障自动切换 |
| LLM ReAct | `internal/aiagent/llm/react_adapter.go` | Thought-Action 范式适配 |

**统一访问** (Service 层调用):
- 业务 Service 通过 `aiagent.GetGlobalRAG()` / `aiagent.GetGlobalLLMDispatcher()` 拿算力
- 业务 Service **不直接**依赖具体厂商

## 跨层调用规则 (强制)

| 上层 | 可调用 | 禁止 |
|---|---|---|
| L1 接入 | L2 Runtime, L4 ToolRegistry | L3 引擎、L6 算力 (必须经 L2/L4) |
| L2 Runtime | L3 Engine, L4 ToolRegistry, L5 Memory, L6 算力 | 任何业务 Service (避免循环) |
| L3 Engine | L4 ToolRegistry, L5 Memory, L6 算力 | 业务 Service |
| L4 Tool | L5 Memory, L6 算力, Repository (包装业务) | 业务 Service |
| L5 Memory | L6 算力 (向量化), Repository | 业务 Service |
| L6 算力 | L5 Memory (向量读), 内部子模块 | 业务 Service, 业务 Controller |

## 验证清单 (CI 集成方向)

- [ ] L1 入口都走 `InboxService.HandleIngressMessage` (方向 3 落地后)
- [ ] L2 Runtime 启动后单例可被任意业务 Service 注入
- [ ] L3 Engine 不直接调 db / redis / 业务 service
- [ ] L4 Tool 通过 `RouteToToolRegistry` 调度，业务 service 仅包装 Tool
- [ ] L5 Memory 四层介质职责不混用 (L1 不持久化，L2 不存明文)
- [ ] L6 算力所有外部厂商 API 走 LLM Dispatcher，无散落 HTTP 调用

## 与五层架构 (GO) 的映射

| 物理拓扑层 | 五层架构归属 |
|---|---|
| L1 接入 | L3 Controller (路由) + L4 Service (InboxService) |
| L2 Runtime | L4 Service (AgentRuntime 包装) + aiagent 内部 agent/runtime |
| L3 Engine | aiagent 内部 agent/ (与业务 Service 平级) |
| L4 Tool | aiagent 内部 tooluse/ (包装 Repository) |
| L5 Memory | L5 Repository (L4 业务实体) + aiagent 内部 vector/ + Redis |
| L6 算力 | aiagent 内部 embedding/ + llm/ + rag/ |

> ⛔ **反向依赖禁止**: 业务 Service 可调 aiagent，但 aiagent 内部禁止调业务 Service。
