# 六层物理拓扑对齐清单

> **关联文档**:
> - 高层架构: `ARCHITECTURE_DIAGRAM.md`
> - 代码规范: `GO_FIVE_LAYER_ARCHITECTURE.md`
> - 模块全景: `功能模块全景图.md` / `功能模块全景对齐清单.md`

本文档固化「六层物理拓扑」与现有代码的逐层映射关系，作为企业级架构优化的基线。
**路径与 API 名以 `user-server` 代码为准**。

---

## 拓扑总览

```
┌────────────────────────────────────────────────────────────────────────┐
│ 1. 接入与渠道层 (Webhook / WebSocket -> InboxIngressService)            │
├────────────────────────────────────────────────────────────────────────┤
│ 2. 智能体运行时 (AgentRuntime: 事件订阅 -> 加载 AgentContext 上下文)   │
├────────────────────────────────────────────────────────────────────────┤
│ 3. 智能体引擎 (InferenceCycle: 感知→对齐→门禁→规划 → bridge 执行)      │
├────────────────────────────────────────────────────────────────────────┤
│ 4. 工具注册表 (ToolRegistry / ToolRouter: customer.* / rag.* / …)      │
├────────────────────────────────────────────────────────────────────────┤
│ 5. 记忆系统 (MemorySystem: L1 短期 → L2 长期 → L3 SOP → L4 业务)       │
├────────────────────────────────────────────────────────────────────────┤
│ 6. AI 算力底座 (Embedding → 本地 RAG → llm.GetGlobalDispatcher)        │
└────────────────────────────────────────────────────────────────────────┘
```

**根路径约定**：下文相对路径默认相对于 `user-server/`，aiagent 全路径为
`internal/aiagent/...`。

## 第 1 层 - 接入与渠道层

| 渠道适配器 | 代码路径 | 职责 | 状态 |
|---|---|---|---|
| 网页客服 | `../embed-sdk/src/iframe-panel.js` + `internal/websocket/` | WebSocket 长连接 + 嵌入聊天窗 | ✅ |
| 闲鱼自动化 | `internal/aiagent/agent/browser/xianyu_ws.go` | 闲鱼 WebSocket 接入 | ✅ |
| 平台机器人 | `internal/aiagent/agent/browser/platform.go` | 平台端浏览器自动化 | ✅ |
| Telegram | `internal/service/telegram_webhook_bootstrap.go` + `telegram_lead_miner.go` + `internal/controller/telegram_account_controller.go` | TG Webhook / 线索挖掘 | ✅ |
| WhatsApp | `internal/service/whatsapp.go` + 相关 controller | WA 出站/入站 | ✅ |
| 站内 Web 入站 | `internal/router/admin_routes.go` → `POST /api/chat/ingress` | 公开 ingress 入口 | ✅ |
| 访客 Chat API | `internal/router/chat_routes.go` → `/api/chat/public/*` | Widget 会话 REST | ✅ |

**统一消息标准**:

- Runtime 载荷：`internal/aiagent/agent/runtime/types.go` → `CustomerMessagePayload`
- 入站事件：`internal/model/message_event.go` → `MessageEvent`

**统一入口（已落地）**:

- Service：`internal/service/inbox_ingress.go` → `InboxIngressService.HandleIngressMessage`
- Controller：`internal/controller/inbox_controller.go`（收件箱列表/操作）+ admin 路由中的 ingress
- 会话中台：`internal/service/message_hub_service.go` / `unified_inbox.go`

> 历史文档中的 `internal/aiagent/agent/inbox/` **不存在**；能力落在 `service.InboxIngressService`。

**处理流程（逻辑）**:

1. 标准化 `MessageEvent`（补 event_id / session_id / timestamp）
2. 人工接管锁命中 → 仅落库，绕过 AI
3. AI 串行锁（SetNX）→ 触发 Runtime / 同步主链路
4. 锁竞争失败 → pending 队列，下轮合并
5. 持久化 message_hub

## 第 2 层 - 智能体运行时 (AgentRuntime)

**代码路径**: `internal/aiagent/agent/runtime/`

| 文件 | 职责 |
|---|---|
| `runtime.go` | 主入口 `HandleCustomerMessage`；按 AgentType 路由 sales / customer_service / hybrid |
| `types.go` | `AgentRuntime` / `AgentContext` / `CustomerMessagePayload` / Bridge 接口 / `NewAgentRuntime` |
| `loader.go` | `NewPGAgentContextLoader`：从 `ai_agents` + `channel_agent_bindings` 加载 |

| `inference_cycle.go` + `*_stage.go` | 认知闭环阶段（L3 主编排） |
| `dataflow_orchestrator.go` | 端到端数据流编排（资产织布 → 推理 → 工具 → 发布） |

**Wiring（生产装配）**:

- 环境变量：`AGENT_RUNTIME_BUS_ENABLED=true` 时开启 Event Bus 订阅；**默认同步主链路仍为 webhook → SmartCS / Runtime.HandleCustomerMessage**

> 文档历史名 `InitGlobalRuntime()` 对应代码：`InitGlobalRuntime` + `NewAgentRuntime(loader, salesBridge, csBridge)`，**不再使用 nil 依赖生产路径**。

## 第 3 层 - 智能体引擎 (Decision Engine)

**主编排（收敛后）**: `InferenceCycle.RunOnce`

```
感知 (Perception) → 对齐 (Alignment 6维) → 门禁 (Gatekeeper) → 规划 (Planner)
        ↓ 若 handoff
   Escalation / 转人工
        ↓ 若 plan_ready
   Bridge 执行（SalesEngine / SmartCS）+ Tool 链
```

| 子模块 | 代码路径 | 职责 |
|---|---|---|
| 引擎包说明 | `internal/aiagent/agent/agent.go` | 领域入口说明（非编排主体） |
| **推理闭环（主）** | `runtime/inference_cycle.go` + `stages.go` | 阶段编排、超时、早退、可观测 |
| 感知阶段 | `runtime/perception_stage.go` | 情绪 + 意图（规则/可注入） |
| 对齐阶段 | `runtime/alignment_stage.go` | 6 维拟人度 |
| 门禁阶段 | `runtime/gatekeeper_stage.go` | 危机检测 → 转人工 |
| 规划阶段 | `runtime/planner_stage.go` | 任务/工具规划 |
| 数据流编排 | `runtime/dataflow_orchestrator.go` | L1/L2 织布 + 工具 + 发布 |
| 销冠执行（适配） | `agent/bridge/sales_bridge.go` → `service.SalesEngine` | LLM 推理 + 9 步链路 |
| 客服执行（适配） | `agent/bridge` SmartCS bridge → `service.SmartCSOrchestrator` | 会话 + 置信度 + 转人工 |
| ReAct 适配 | `internal/aiagent/llm/react_adapter.go` | Thought-Action 范式 |
| 工具执行 | `agent/tooluse/executor.go` | Tool 调度 |
| 规则门禁（辅助） | `agent/auto_reply/rule_matcher.go` | 自动回复规则 |
| 对话管理（辅助） | `rag/customer_service/dialog_manager.go` | 客服对话状态 |

**原则**:

- **InferenceCycle 是决策大脑主路径**；SalesEngine / SmartCS 仅作为 Action 阶段的 Bridge 适配器。
- `agent.go` 不承担编排，只做领域说明与 Mode 辅助。

## 第 4 层 - 工具注册表 (Tool Registry)

**代码路径**: `internal/aiagent/agent/tooluse/`

| 文件 | 工具分类 | 说明 |
|---|---|---|
| `registry.go` | 注册中心 | `Register` / `Get` / `List` / `GetGlobalRegistry()` |
| `tool_router.go` | 统一路由中枢 | `ToolRouter.Route`（限流/熔断/成本统计） |
| `executor.go` | 执行器 | 装饰器链入口 `GetGlobalExecutor()` |
| `customer_tools.go` | customer.* | 依赖 **CustomerPort**（接口注入） |
| `knowledge_tools.go` | knowledge.* / rag.* | 知识检索 |
| `reach_tools.go` | reach.* | 依赖 **ReachAdapter / ReachPipelinePort** |
| `business_tools.go` | business.* | 依赖 **OrderPort / FollowUpPort** |
| `private_message_tools.go` | pm.* | 依赖 **SessionPort** |
| `decorator.go` 等 | 横切 | rate_limit → retry → audit → billing |

**统一结果结构（以代码为准）**:

```go
type ToolResult struct {
    Success    bool       `json:"success"`
    Data       any        `json:"data,omitempty"`
    Error      string     `json:"error,omitempty"`
    Timing     ToolTiming `json:"timing"`
    ToolName   string     `json:"tool_name"`
    ExecutedAt time.Time  `json:"executed_at"`
}
```

> 历史文档中的 `ToolResponse{Status,Data}` / `RouteToToolRegistry` 已废弃，统一为 `ToolResult` + `ToolRouter.Route`。

**依赖铁律**:

- tooluse **只依赖接口（ports）与 repository/model**，不 import 具体 `internal/service` 实现类型作为硬依赖（装配时由 service 适配器注入）。
- 业务 Service **可**包装并注册 Tool；Tool **不可**反向持有具体 Service 结构体类型。

## 第 5 层 - 记忆系统 (Memory System)

**统一入口（以代码为准）**: `internal/service/memory_system.go` → `MemorySystem`

| 层级 | 介质（实现） | API | 职责 |
|---|---|---|---|
| L1 短期 | **PostgreSQL** `MemoryItem`（滑动窗口默认 10 条，TTL 24h）；可选 Redis 加速检索缓存 | `L1Append` / `L1List` / `L1Clear` | 当前会话连贯性 |
| L2 长期 | PostgreSQL 事实/摘要 + **pgvector 增强**（`Remember` / `Recall`） | `L2SaveFact` / `L2ListFacts` / `Remember` / `Recall` | 用户标签、偏好、摘要 |
| L3 SOP | PostgreSQL `SOPStateMemory`（与 sop_executions 协同） | `L3SaveSOPState` / `L3GetSOPState` | 流程进度 |
| L4 业务 | PostgreSQL `BusinessMemory` + 业务表（order/clue/user） | `L4Record` / `L4ListByCustomer` | 订单/工单/意向快照 |

**相关路径**:

- 向量模型：`internal/aiagent/vector/vector_model.go`（非 `internal/vector/`）
- RAG 检索缓存：`internal/aiagent/rag/retrieval/redis_cache.go`（**检索缓存**，≠ L1 对话记忆）
- SOP 服务：`internal/service/sop_service.go` + `sop_loader.go`（非 `sop.go`）
- 全量上下文：`MemorySystem.BuildFullContext`

**写入约定**:

- L1：会话响应后由 Runtime / DialogueMemory 同步路径调用 `L1Append`
- L2：异步提炼走 `Remember` / `L2SaveFact`（publisher_knowledge 可触发）
- L3：SOP 节点推进时 `L3SaveSOPState`
- L4：业务事务完成后 `L4Record` 或业务 Repository 写实体

> 历史文档「L1=Redis 最近 3 轮明文 / RefreshUserVector / AdvanceNode」**已废弃**；以 `MemorySystem` API 为准。

| 子能力 | 代码路径 | 关键能力 |
|---|---|---|
| Embedding | `internal/aiagent/embedding/embedding.go` + `llm/embedding_service.go` | 本地/TEI 向量化 |

| RAG 检索 | `internal/aiagent/rag/retrieval/` | hybrid / rrf / reranker 等 |

```go
llm.GetGlobalDispatcher()   // main: llm.InitGlobalDispatcher(...)
```

业务 Service **不直接**依赖具体厂商 HTTP 客户端，一律经 Dispatcher。

## 跨层调用规则 (强制)

| 上层 | 可调用 | 禁止 |
|---|---|---|
| L1 接入 | L2 Runtime, L4 ToolRegistry（经统一入口） | 绕过 Runtime 直接调 L6 厂商 API |
| L2 Runtime | L3 Cycle, L4 Tool, L5 Memory, L6 算力 | 直接 import 业务 Service 具体实现（经 Bridge 接口） |
| L3 Engine | L4 Tool, L5 Memory, L6 算力 | 直接调业务 Service |
| L4 Tool | L5 Memory, L6 算力, Repository, **业务 Port 接口** | 硬编码 `*service.XxxService` 类型 |
| L5 Memory | L6 算力（向量化）, Repository | 业务 Controller |
| L6 算力 | L5 向量读, 内部子模块 | 业务 Service / Controller |

> ⛔ **反向依赖禁止**: 业务 Service 可调 aiagent；aiagent 内部禁止 import 业务 Service 实现（允许 dto/model/repository + 接口）。

## 与五层架构 (GO) 的映射

| 物理拓扑层 | 五层架构归属 |
|---|---|
| L1 接入 | L3 Controller + L4 Service（InboxIngress / Webhook） |
| L2 Runtime | aiagent/agent/runtime + 启动 Wiring |
| L3 Engine | InferenceCycle（主）+ bridge → service 引擎（适配） |
| L4 Tool | aiagent/agent/tooluse（Port 注入） |
| L5 Memory | service.MemorySystem + aiagent/vector + 可选 Redis |
| L6 算力 | aiagent/embedding + llm + rag |
