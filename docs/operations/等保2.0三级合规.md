# 等级保护 2.0 三级合规方案（2026-08-15 M3-P1-E8）

> HiveMtk 在金融 / 医疗 / 政务等强合规行业的等保 2.0 三级合规方案。本文档描述了系统如何满足等保 2.0（GB/T 22239-2019）三级要求的所有技术项。

---

## 1. 适用范围

| 行业 | 等保级别 | 强制要求 |
|------|---------|---------|
| 金融（银行/保险/证券） | 三级 | 强制 |
| 医疗（三级医院） | 三级 | 强制 |
| 政务（政府/事业单位） | 三级 | 强制 |
| 能源 / 交通 / 通信 | 三级 | 强制 |
| 互联网 | 二级 | 推荐三级 |
| 一般企业 | 二级 | 推荐三级 |

## 2. 安全通信网络

### 2.1 网络架构

| 要求项 | 三级要求 | 实现 |
|--------|---------|------|
| 划分网络区域 | 应划分安全域 | 5 层架构天然分层 |
| 边界防护 | 部署边界设备 | Nginx + WAF + 防火墙 |
| 访问控制 | ACL 控制 | PostgreSQL GRANT + Redis ACL |
| 入侵防范 | 入侵检测 | fail2ban + 审计日志异常告警 |
| 恶意代码防范 | 防病毒 | ClamAV 文件扫描 |

### 2.2 通信加密

| 协议 | 实现 |
|------|------|
| HTTPS | TLS 1.2+（推荐 1.3），证书 90 天自动续期 |
| WebSocket | wss://（强制 TLS） |
| 数据库连接 | SSL 强制（PG `sslmode=require`） |
| Redis 连接 | TLS 1.2+（`rediss://`） |
| 内部通信 | mTLS（自签 CA + 证书轮换） |

### 2.3 网络拓扑

```
Internet → WAF → LB (Nginx) → App (user-server × 3) → DB (PG × 3)
                  ↓                              ↓
              监控 (Prometheus)              Cache (Redis Sentinel)
              日志 (Loki)                    搜索 (ES 集群)
```

## 3. 安全区域边界

### 3.1 边界设备配置

| 设备 | 配置 |
|------|------|
| 防火墙 (iptables/nftables) | 默认拒绝，按需放通 |
| WAF (ModSecurity) | OWASP Top 10 规则集 |
| 入侵检测 (Suricata) | 异常流量告警 |
| API 网关 | 限流 / 鉴权 / 审计 |

### 3.2 访问控制策略

```nginx
# Nginx 白名单（管理后台）
location /api/admin/ {
    allow 192.168.0.0/16;    # 内网
    allow 10.0.0.0/8;
    deny all;
}

# 桥接扩展专用 API
location /api/bridge/ {
    # 仅扩展调用，Token 鉴权
    if ($http_authorization = "") {
        return 401;
    }
}
```

## 4. 安全计算环境

### 4.1 身份鉴别

| 要求 | 实现 |
|------|------|
| 唯一性标识 | user_id (主键), username (唯一索引) |
| 双因素认证 | TOTP (RFC 6238) + SMS 备份码 |
| 密码强度 | ≥ 12 位，含大小写数字符号 |
| 登录失败处理 | 5 次失败 → 锁定 30 分钟 |
| 登录日志 | 审计中间件记录 |

**对应文件**：
- `user-server/internal/middleware/brute_force.go` - 暴力破解防护
- `user-server/internal/middleware/mfa.go` - 双因素认证
- `user-server/internal/middleware/audit.go` - 审计日志

### 4.2 访问控制

| 要求 | 实现 |
|------|------|
| 最小权限 | RBAC 角色：admin / manager / agent / user |
| 强制访问控制 | 5 层架构：Controller 不能直访 DB |
| 安全标记 | data_scope: all / department / self |
| 访问控制粒度 | 行级（通过 team_id / department_id 过滤） |

**对应文件**：
- `user-server/internal/middleware/permission.go` - RBAC
- `user-server/internal/middleware/require_admin.go` - 管理员权限

### 4.3 安全审计

| 要求 | 实现 |
|------|------|
| 审计范围 | 全量 API（POST/PUT/DELETE/PATCH） |
| 审计内容 | who / when / from_ip / action / resource / result / trace_id |
| 审计存储 | 异步批量入库，独立表 audit_logs |
| 审计保护 | 1 年保留 + 异地备份 |
| 审计告警 | 异常登录、高频失败、跨账号访问 |

**对应代码**：

```go
// user-server/internal/middleware/audit.go
entry := &AuditEntry{
    UserID:     convertToUint(userID),
    Username:   convertToString(username),
    Action:     getActionFromMethod(method),
    Module:     getModuleFromPath(path),
    Resource:   getResourceFromPath(path),
    ResourceID: getResourceIDFromPath(path),
    Detail:     string(detailJSON),
    IP:         c.ClientIP(),
    UserAgent:  c.Request.UserAgent(),
    TraceID:    getTraceID(c),
}
```

### 4.4 入侵防范

| 要求 | 实现 |
|------|------|
| 最小安装 | Docker 镜像仅含必要包 |
| 漏洞修补 | Dependabot 自动 PR，每周扫描 |
| 恶意代码防范 | ClamAV 上传文件扫描 |
| 应用层防护 | WAF + 限流 + 输入校验 |
| 异常行为 | 审计告警：高频操作、敏感接口访问 |

### 4.5 数据完整性

| 要求 | 实现 |
|------|------|
| 传输完整性 | TLS 1.2+ |
| 存储完整性 | PostgreSQL CRC 校验 + WAL |
| 备份完整性 | 每周自动验证脚本 |

### 4.6 数据保密性

| 要求 | 实现 |
|------|------|
| 传输保密 | TLS 1.2+（强制） |
| 存储保密 | 密码 bcrypt (cost=12)，敏感字段 AES-256-GCM |
| 密钥管理 | 30 天轮换，HSM 可选 |
| 脱敏 | 日志 / 响应中 PII 字段自动脱敏 |

**对应文件**：
- `user-server/internal/middleware/sanitize.go` - 脱敏中间件
- `user-server/internal/pkg/utils/crypto.go` - AES-256-GCM 加密

### 4.7 备份与恢复

| 要求 | 实现 |
|------|------|
| 重要数据备份 | 每日 02:00 异地备份 |
| 备份验证 | 每周自动恢复验证 |
| 恢复演练 | 季度 PITR 演练 |

## 5. 安全管理中心

### 5.1 系统管理

| 要求 | 实现 |
|------|------|
| 管理员分权 | 超级管理员 / 审计管理员 / 安全管理员 三权分立 |
| 操作审计 | 所有 admin 操作记录 |
| 密码策略 | 90 天强制更换，强度 ≥ 12 位 |

### 5.2 审计管理

| 要求 | 实现 |
|------|------|
| 审计员 | 独立 audit_admin 角色（只读审计日志） |
| 审计保护 | 审计表禁止 DELETE/UPDATE（仅 INSERT） |
| 审计导出 | 按时间范围 / 用户 / 操作类型导出 |

```sql
-- audit_logs 表结构
CREATE TABLE audit_logs (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT NOT NULL,
    username VARCHAR(64) NOT NULL,
    action VARCHAR(32) NOT NULL,
    module VARCHAR(64) NOT NULL,
    resource VARCHAR(64) NOT NULL,
    resource_id VARCHAR(128),
    detail JSONB,
    ip INET,
    user_agent TEXT,
    trace_id VARCHAR(64),
    created_at TIMESTAMPTZ DEFAULT NOW()
);

-- 禁止修改（仅 INSERT）
REVOKE UPDATE, DELETE ON audit_logs FROM hivemtk_app;

-- 索引（按时间 + 用户查询）
CREATE INDEX idx_audit_user_time ON audit_logs (user_id, created_at DESC);
CREATE INDEX idx_audit_action ON audit_logs (action, created_at DESC);
```
